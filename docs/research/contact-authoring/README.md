# Atomic contact authoring — development checkpoint

New command-registry operations capture a planted/sliding/free key, edit its blend/reference, edit a shared reference pose, move a key without overwriting another, or delete a key without deleting a still-used reference. They use one exact SetLoomRigs Undo/Redo transaction; validation occurs before commit. Typed JSON schemas expose the actual key/reference fields. Commands operate on rig metadata and leave all source node controllers untouched.

Full-IK planted/sliding capture uses the current solved end pose and bend plane at the requested time. World references stay world-space. Free captures a Body reference with blend0; Body uses the characterized root frame. Capture converts a desired proper world rotation into the local body rotation using the proper-polar reflection convention, rather than decomposing a skewed matrix. Evaluation time is restored after capture. Planted reuses a prior full/partial-IK World reference only if its pose matches the new stance; it does not snap a different stance to an old anchor. A Free span starts a new reference. Shared identity can also be edited explicitly through the key command.

## Real Ray finding and correction

The first production-scene test failed on Left Leg: its start bone X axis was nearly unchanged, but its Y/Z axes changed drastically. The retained diagnostic matrices show this was an axial-roll change. The analytic Limb solver constructs canonical perpendicular frames when a positional correction is needed; source roll was not retained by that path. The small fixture had not exposed the problem.

Contacts now use a separate roll-preserving Limb path: retain the analytic joint positions and apply the minimum swing from each input bone orientation to its solved segment. The ordinary solve function and legacy empty-contact path remain unchanged. A dedicated test verifies tiny-motion roll continuity and equality of analytic elbow/end positions for both small and larger motions. Its initial generic rotation-arc implementation failed the small positional-correction test because the near-parallel arc snapped to identity; the same explicit small-angle quaternion construction used by HI fixes that case.

The production Ray test loads the real unmodified source scene through Open File, samples frame39, captures each arm and leg separately, compares start/middle/end world matrices (absolute component tolerance0.003), verifies no contact errors, fingerprints all source node records and materials, then Undoes each capture. It passed after the roll correction. This is real Scene/command evaluation, not native viewport or GPU rendering certification.
